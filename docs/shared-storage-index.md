# Shared generated-water storage index: milestone C3n

Status: implemented as bounded headless `seeded-multi-entry-network-4`, September 29, 2026. This is a storage-representation change for the generated-water experiment, not a desktop water cycle or an increase of the supported resolution ceiling. Newly generated starts above 128 regions use v4; v1–v3 checkpoint restores retain their original algorithms and admission limits.

## Representation and numerical contract

Earlier expanded versions built a complete `Reservoir` curve for every basin branch. Each ancestor duplicated every regional column of its descendant branches. V4 keeps the canonical regional columns in its checkpoint and builds one deterministic region-ID ordering grouped by the exclusive owning branch's depth-first number. All columns belonging to a branch's subtree occupy one contiguous range of that ordering. The derived index has one region ID per region, one range and two height bounds per branch, plus one sorted list of distinct bed heights. It does not store any per-branch copy of a column or storage curve.

A branch-volume query scans its subtree range and sums the nonnegative regional prisms `area × max(level - bed, 0)` using compensated summation. A level-from-volume query searches the sorted elevation breakpoints and inverts the piecewise-linear segment using the scanned wetted area. This trades increased query work for index memory of `O(N + K)` rather than duplicated curve storage proportional to the sum of subtree sizes. A level query can scan an entire subtree; inverse queries can perform multiple such scans. The rest of the model still has other geometry, adjacency, rate-vector and event costs; this is **not** a general `O(N)` solver or an unrestricted planet-scale implementation.

V4 retains [C3m's exact limiting-capacity rule](exact-limit-commit.md), the same input/initial ledgers, event policy, reconstruction and budget audits, atomic interval failure, and generated-recipe provenance. It has a new experiment version because changed summation order or reconstructed levels can change floating-point results. Derived ranges are rebuilt on restore; they are not new unrecorded checkpoint state. C3l's 500,000-reference cap still applies to v2/v3 but is irrelevant to v4, which allocates no such duplicate curves. V4 remains bounded to 10,242 regions, 100,000 edges, 2,048 branches and depth 128. Its 10,242-region ceiling and unit weights are experiment limits, not calibrated physical laws.

The compact profiler now emits `reportVersion: 2`, `storageRepresentation`, and `logicalSubtreeColumnReferences`. The latter is a hypothetical count of how many column references a duplicated representation would require, **not** a v4 allocation count. Previous v2/v3 profile reports remain historical report-v1 data.

## Reproducible evidence

The fixed [20-seed release-profile sample](data/shared-storage-profile.csv) at subdivision 5, 25% initial water coverage and 2 × 10^14 m³ at region 3 accepted 20/20 runs in v4. All accepted full-ledger residuals had absolute value at most 22 m³ under the existing relative tolerance. In particular, `profile-06`, `profile-16` and `profile-17` now pass; v3 still rejects their checkpoint preparation at its explicit duplicate-reference cap. No failed seed was omitted. This is one large prescribed input and a small fixed engineering sample, not an acceptance rate for arbitrary worlds, distributed rainfall or years of dynamics.

One release-process observation on the same AMD Ryzen 5 PRO 4650U laptop for `first-light`, subdivision 5: preparation 179.97 ms, one interval 1.06 ms, Linux process peak RSS 22,560 KiB. The earlier [C3l v2 observation](expanded-seeded-network.md) was 158.85 ms, 0.325 ms and approximately 35.2 MiB respectively. These are separate single runs, not controlled throughput benchmarks; preparation includes world verification and other overhead, and process RSS is not isolated index memory. They do illustrate the tradeoff: less observed process memory, more observed interval work. Across subdivisions 2–5 in one v4 pass, all four runs completed; the 10,242-region case had 451 branches and 411,318 *logical* subtree-column references but stores only 10,242 ordered region IDs in this index.

Tests compare every nested prism on a constructed weighted bowl with independently assembled legacy reservoirs, check that the region ordering contains each region exactly once, and compare v2/v4 active branch stocks on a generated world. V1–v3 replay and their old failure rules remain under test. The three previously capped seeds are regression cases. Four distributed-input intervals on a 642-region generated world compare uninterrupted execution with serialized checkpoint continuation after every interval, including ledgers and events. This is a short smoke sequence, not long-term numerical stability evidence.

The Rust checkpoint type can serialize and restore the tested generated state, but the existing `seeded_network` developer CLI still caps an entire request at 32 KiB. A full 10,242-region checkpoint generally exceeds that CLI input limit; this milestone does not claim large-checkpoint CLI resume or a desktop save/load path. The compact `seeded_profile` tool intentionally avoids serializing the full checkpoint.

Validation on September 29, 2026: `npm test`, Rust formatting, Clippy across all targets with warnings denied, and `npm run test:desktop` passed. The desktop fingerprint remained `2e66ac09`; no renderer or native wire-protocol feature changed. The existing Vite chunk-size advisory remains.

## Remaining gate

[C3o](repeated-forcing-probe.md) now measures two 100-interval cyclic input sweeps: eight atomic event-budget rejections at the larger input scale and seven water-level representation rejections at a smaller scale, each in a fixed 20-seed sample. Before connecting water to the desktop, resolve those distinct numerical failures, test many more seeds and water/forcing regimes, small continuous inputs, exact dry-sill states and visible surface reconstruction after merges. The current rate traversal still clones branch vectors at nested states; repeated subtree scans may become the next CPU bottleneck. Sub-precision pending water, drying and splitting, finite travel time, climate-driven rain and river discharge remain unimplemented.
